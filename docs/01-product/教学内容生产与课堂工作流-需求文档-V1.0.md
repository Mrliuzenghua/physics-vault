# 教学内容生产与课堂工作流需求文档

> 文档版本：V1.0
> 编写日期：2026-08-05
> 适用产品：Physics Vault 3.0
> 文档状态：产品架构重审稿
> 覆盖范围：组卷工作台、讲义排版、课件制作、课堂授课、模板中心、MCP 能力及其共享数据链路

---

## 1. 文档目的

本需求文档重新定义 Physics Vault 从题库选题到课堂使用的完整教学内容生产流程，解决当前系统中以下问题：

1. 组卷工作台承担了过多排版、打印、课件和授课入口功能，主任务不够聚焦。
2. 题目加入试卷后虽然可以在界面编辑，但当前草稿主要保存题库题号，重新加载后仍可能读取题库原题，文档内修改缺少可靠持久化。
3. 讲义、课件、课堂授课之间既共享内容又各自需要独立调整，现有关系表达不清。
4. 模板同时混合内容生成规则、打印样式、答案显示策略和课件配置，难以理解模板会改变什么。
5. 课堂授课读取“当前内容”，缺少稳定的发布版本，上课期间存在内容被编辑状态影响的风险。
6. 本地存储、服务端草稿、已保存讲义和教学项目存在多套数据来源，缺少唯一可信对象。

本文档的目标不是为五个页面分别罗列按钮，而是建立一套可持续演进的产品模型：

> 以“教学项目”为容器，以“可编辑教学内容”为唯一内容源，以讲义和课件为独立产物，以已发布课件版本驱动课堂授课，以作用域明确的模板提升复用效率。

---

## 2. 产品定位

Physics Vault 不只是题库和组卷工具，而应成为教师完成一次教学任务的内容生产工作台：

```text
题库检索与选题
    ↓
建立教学项目
    ↓
编排并修改教学内容
    ├─ 生成讲义 → 排版 → PDF / Word / 打印
    └─ 生成课件 → 编辑 → 发布 → 课堂授课
    ↓
沉淀为模板、版本和可复用作品
```

核心价值：

1. 题库内容可以快速进入当前教学任务，并在不污染题库原题的前提下自由修改。
2. 一次内容编排可以生成学生讲义、教师讲义和课堂课件。
3. 讲义与 PDF 所见即所得，课件与授课所见一致。
4. 内容变更有来源、有版本、有同步提示，不静默覆盖人工调整。
5. 教师完成一次教学任务后，可以把结构、样式或完整项目沉淀为模板。

## 3. 用户与核心场景

### 3.1 主要用户

首期主要面向单机或私有化环境下的高中物理教师。

后续可扩展角色：

- 备课组长：维护公共模板、审核题目和共享教学项目。
- 学科管理员：维护题库、知识体系和学校级视觉规范。
- 授课教师：只使用已发布课件进行课堂展示和批注。

### 3.2 核心场景

#### 场景 A：从题库快速组一份练习

教师从题库选择 10 道题，调整顺序、题号和分值，修改其中两道题的设问，生成学生版 PDF 和带解析教师版。

#### 场景 B：制作知识点讲义

教师围绕一个知识点选择例题和训练题，插入知识讲解、方法总结和易错提醒，在讲义排版中控制分页、图片大小和答题留白。

#### 场景 C：基于同一内容制作课堂课件

教师把教学内容生成课件，将一道综合题拆成“题干—条件分析—关键步骤—答案”多页，添加课堂提问页，并发布为可授课版本。

#### 场景 D：课堂授课

教师打开已发布课件，全屏播放，分步揭示答案和解析，进行临时批注；授课过程不受后台继续编辑课件的影响。

#### 场景 E：复用成熟方案

教师把本次项目的组卷结构保存为内容结构模板，把讲义版式保存为讲义样式模板，把课件视觉方案保存为课件主题模板，下次可以分别复用。

## 4. 核心产品原则

### 4.1 题库是来源，不是当前文档

题目进入教学项目时，必须生成“项目题目实例”。项目题目实例保留题库来源，但拥有完整、独立、可编辑的内容副本。

默认规则：

- 修改项目题目只影响当前教学项目。
- 题库原题后续更新，不自动覆盖项目题目。
- 教师可以主动比较题库新版本与项目版本。
- 写回题库必须通过明确操作和权限校验。

### 4.2 内容与表现分离

- 组卷工作台负责内容选择、结构和教学语义。
- 讲义排版负责纸张上的视觉表现。
- 课件制作负责屏幕页面和讲授节奏。
- 课堂授课负责播放和临时课堂状态。
- 模板中心负责复用规则，不直接承担内容编辑。

### 4.3 一个项目，多种产物

讲义和课件来自同一份教学内容，但各自拥有独立的表现配置和人工调整。

### 4.4 草稿实时共享，发布版本冻结

- 编辑阶段：组卷内容修改后，讲义草稿实时读取最新内容；课件提示是否同步。
- 发布阶段：生成不可变的讲义发布版本或课件发布版本。
- 授课阶段：只读取指定的已发布课件版本。

### 4.5 不静默覆盖人工修改

任何自动生成、AI 改写、模板应用或内容同步，只要可能覆盖教师人工调整，都必须提供差异说明和确认范围。

### 4.6 预览必须代表真实输出

- 讲义预览与 PDF 必须使用同一分页结果。
- 课件编辑预览与课堂播放必须使用同一课件版本和渲染组件。
- Word 只保证内容与基础样式一致，不承诺与浏览器 PDF 像素级同页。

## 5. 总体信息架构

### 5.1 顶层对象

新增统一的“教学项目”概念。一个教学项目包含：

```text
教学项目
├─ 基本信息
├─ 教学内容文档
│  ├─ 标题与说明
│  ├─ 章节 / 大题
│  ├─ 知识卡
│  ├─ 项目题目实例
│  └─ 其他内容块
├─ 讲义产物
│  ├─ 学生版配置
│  ├─ 教师版配置
│  ├─ 分页与局部排版
│  └─ 发布 / 导出版本
├─ 课件产物
│  ├─ 幻灯页
│  ├─ 逐步揭示设置
│  ├─ 主题与布局
│  └─ 发布版本
├─ 课堂会话
│  ├─ 使用的课件发布版本
│  ├─ 播放位置
│  └─ 临时批注
└─ 模板引用与版本历史
```

### 5.2 建议导航

顶层导航保留五个清晰入口：

1. 组卷与内容
2. 讲义排版
3. 课件制作
4. 课堂授课
5. 模板中心

进入某个教学项目后，五个入口应保持同一个 `projectId`：

```text
/projects/:projectId/compose
/projects/:projectId/handout
/projects/:projectId/slides
/projects/:projectId/classroom
/templates
```

页面顶部统一显示：项目名称、内容版本、保存状态、产物状态以及模块切换。

### 5.3 教学项目首页

建议新增教学项目首页或作品库，显示：

- 最近编辑的项目。
- 项目内容摘要和题目数量。
- 讲义状态：未创建、草稿、待同步、已发布。
- 课件状态：未创建、草稿、待同步、已发布。
- 最近一次授课时间。
- 复制项目、归档、删除和基于模板新建。

项目首页是作品管理入口，不应由讲义页和课件页分别维护重复的文件树。

### 5.4 工作流按项目类型裁剪

五个模块是可组合能力，不是每个项目都必须经过的固定向导。新建项目时选择用途，系统据此提供默认结构和推荐下一步：

| 项目类型 | 主要流程 | 通常跳过 |
|---|---|---|
| 测验 / 考试 | 组卷与内容 → 讲义排版 → PDF / Word | 课件、授课 |
| 练习 / 作业 | 组卷与内容 → 讲义排版 | 课件、授课 |
| 新授课 | 组卷与内容 → 讲义和课件 → 发布 → 授课 | 无强制跳过 |
| 复习课 | 组卷与内容 → 讲义和课件 → 授课 | 无强制跳过 |
| 课堂例题 | 组卷与内容 → 课件 → 授课 | 讲义可选 |

项目类型只影响默认界面和推荐流程，不限制教师后续创建任何产物。系统不得为了保持流程完整而强迫纯试卷项目创建课件。

## 6. 统一数据模型

### 6.1 教学项目

```ts
interface TeachingProject {
  id: string;
  title: string;
  subject: 'physics';
  projectType: 'exam' | 'worksheet' | 'homework' | 'lesson' | 'review' | 'classroomExample';
  grade?: string;
  term?: string;
  tags: string[];

  contentDocumentId: string;
  handoutArtifactIds: string[];
  slideArtifactIds: string[];

  status: 'draft' | 'ready' | 'archived';
  createdAt: string;
  updatedAt: string;
}
```

### 6.2 教学内容文档

教学内容文档是组卷、讲义和课件共享的唯一内容源。

```ts
interface TeachingContentDocument {
  id: string;
  projectId: string;
  revision: number;
  title: string;
  subtitle?: string;
  nodes: TeachingContentNode[];
  createdAt: string;
  updatedAt: string;
}
```

首期内容节点：

- `section`：章节、大题或教学阶段。
- `question`：项目题目实例。
- `knowledgeCard`：知识讲解、方法总结或易错提醒。
- `richText`：普通说明、导语、课堂提示和小结。
- `pageBreakHint`：内容层面的章节起始提示，不等同于某种输出中的绝对分页。

后续节点：

- `table`
- `experimentBlock`
- `answerArea`
- `media`
- `interactiveActivity`

### 6.3 项目题目实例

项目题目实例必须保存完整内容，不得只保存题库题号或浅层覆盖字段。

```ts
interface ProjectQuestionInstance {
  id: string;
  projectId: string;

  origin: {
    type: 'questionBank' | 'custom' | 'generated';
    questionId?: string;
    sourceVersion?: number;
    importedAt: string;
  };

  content: {
    questionType: string;
    stem: RichTextDocument;
    options: QuestionOption[];
    subQuestions: SubQuestion[];
    answer: RichTextDocument;
    analysis: RichTextDocument;
    figures: FigureReference[];
    sourceText?: string;
  };

  teaching: {
    score?: number;
    difficulty?: number;
    knowledgePointIds: string[];
    role: 'example' | 'practice' | 'homework' | 'assessment';
    teacherNotes?: RichTextDocument;
  };

  changeState: {
    changedFromSource: boolean;
    changedFields: string[];
    lastComparedSourceVersion?: number;
  };
}
```

关键要求：

1. 加入项目时复制题目完整内容和媒体引用。
2. 项目内编辑直接更新 `content`，并增加内容文档版本。
3. 题目图片尺寸等讲义表现属性不得写回题库图片元数据。
4. 项目内可以存在同一题库题目的两个不同实例，用于不同设问或不同讲解版本。
5. 从题库删除原题后，已存在的项目题目仍可正常使用。

### 6.4 讲义产物

```ts
interface HandoutArtifact {
  id: string;
  projectId: string;
  name: string;
  profile: 'student' | 'teacher' | 'custom';
  liveContentRevision: number;
  layoutRevision: number;
  globalStyle: HandoutGlobalStyle;
  blockLayouts: Record<string, HandoutBlockLayout>;
  status: 'draft' | 'ready' | 'published';
}
```

讲义产物不复制题目文本，而是通过稳定的内容节点 ID 读取当前内容。发布时才冻结完整快照。

### 6.5 课件产物

```ts
interface SlideArtifact {
  id: string;
  projectId: string;
  name: string;
  sourceContentRevision: number;
  revision: number;
  pages: SlidePage[];
  themeId: string;
  status: 'draft' | 'ready' | 'published';
}
```

每个自动生成的课件页记录 `sourceNodeIds`。人工新建页可以没有来源节点。

### 6.6 发布版本

```ts
interface PublishedArtifactVersion {
  id: string;
  artifactId: string;
  artifactType: 'handout' | 'slides';
  version: number;
  contentRevision: number;
  snapshot: unknown;
  createdAt: string;
}
```

发布版本不可原地修改。修改后需要创建新版本。

## 7. 跨模块工作流

### 7.1 主流程

```text
从题篮或模板新建教学项目
    ↓
组卷与内容编排
    ├─ 保存内容版本
    ├─ 打开讲义排版
    │    ├─ 学生版 / 教师版
    │    ├─ 打印检查
    │    └─ 导出 PDF / Word
    └─ 生成或同步课件
         ├─ 编辑课件
         ├─ 预演
         └─ 发布课件版本
              ↓
          开始课堂授课
```

### 7.2 内容变更传播规则

| 变更 | 讲义草稿 | 课件草稿 | 已发布讲义 | 已发布课件 | 正在授课 |
|---|---|---|---|---|---|
| 修改题干 | 立即更新并重新分页 | 标记待同步 | 不变 | 不变 | 不变 |
| 修改答案解析 | 立即更新教师版 | 标记待同步 | 不变 | 不变 | 不变 |
| 调整内容顺序 | 立即更新 | 标记待同步 | 不变 | 不变 | 不变 |
| 修改讲义页边距 | 仅当前讲义变化 | 不变 | 不变 | 不变 | 不变 |
| 修改课件页顺序 | 不变 | 当前课件变化 | 不变 | 不变 | 不变 |
| 发布新课件 | 不变 | 状态变为已发布 | 不变 | 新增版本 | 下次授课可选择新版本 |

### 7.3 课件同步策略

课件是派生产物，允许人工调整，因此不能在内容变更后自动全部重建。

同步时按页面处理：

- 未人工修改的自动生成页：允许自动更新。
- 已人工修改的来源页：显示差异，教师选择保留、合并或重新生成。
- 来源节点被删除：标记为“来源已删除”，教师决定保留为独立页或删除。
- 新增内容节点：显示为可添加课件页，不强制插入。

## 8. 组卷与内容工作台需求

### 8.1 工作台目标

帮助教师确定“教什么、练什么、内容顺序是什么”，不负责纸张分页和课件视觉设计。

### 8.2 页面布局

建议采用三栏结构：

- 左栏：项目结构树，包括章节、知识卡、题目和文本块。
- 中栏：当前内容编辑区，显示连续内容而非模拟纸张分页。
- 右栏：当前对象属性和教学属性。

顶部只保留：

- 项目标题与保存状态。
- 撤销、重做。
- 添加内容。
- 组卷规则与内容检查。
- 进入讲义排版。
- 进入课件制作。

不得放置：

- A4/A3、页边距、页眉页脚、打印缩放。
- Word/PDF 导出。
- 课件主题和幻灯布局。
- 课堂全屏和播放控制。

### 8.3 内容结构能力

| 编号 | 需求 | 优先级 |
|---|---|---|
| CMP-001 | 从题篮、题库搜索结果或收藏加入题目 | P0 |
| CMP-002 | 新增、删除、复制、替换和拖动题目 | P0 |
| CMP-003 | 插入章节、大题、知识卡、文本说明 | P0 |
| CMP-004 | 设置题目分值、用途、难度和知识点 | P0 |
| CMP-005 | 按知识点、难度、题型自动组织内容，并在确认后应用 | P1 |
| CMP-006 | 检查题量、总分、知识点覆盖、难度分布和题型约束 | P1 |
| CMP-007 | 支持从结构模板创建内容框架 | P1 |

### 8.4 项目题目编辑

| 编号 | 需求 | 优先级 |
|---|---|---|
| QED-001 | 加入项目时创建完整题目实例并服务端持久化 | P0 |
| QED-002 | 编辑题干、选项、子问、答案、解析和题图 | P0 |
| QED-003 | 编辑结果同时在组卷、讲义、课件同步入口中可见 | P0 |
| QED-004 | 默认修改不影响题库原题 | P0 |
| QED-005 | 显示题库来源、来源版本和“已修改”状态 | P1 |
| QED-006 | 对比题库最新版本与项目题目 | P1 |
| QED-007 | 支持“仅更新当前项目”“另存为题库新题”“更新题库原题” | P1 |
| QED-008 | 新建不属于题库的项目自定义题目 | P0 |

### 8.5 内容检查

离开工作台前可执行内容检查：

- 题干为空。
- 选项编号重复或缺失。
- 答案为空。
- 解析为空，仅作为提示，不阻止学生版生成。
- 图片缺失。
- LaTeX 无法渲染。
- 分值未设置或总分异常。
- 重复题目或疑似重复题目。
- 项目题目与题库来源已经发生版本分歧。

### 8.6 保存与恢复

- 所有内容节点和题目完整内容必须写入服务端草稿。
- 自动保存采用递增版本号和乐观并发控制。
- 冲突时不得用服务端旧内容直接覆盖当前编辑；应提供恢复本地、采用服务端或查看差异。
- 本地存储仅用于临时恢复，不得作为项目的唯一可信数据源。

## 9. 讲义排版需求

### 9.1 工作台目标

将教学内容转换为可打印讲义，提供接近 Word 的独立纸张分页体验，并保证预览与 PDF 输出一致。

### 9.2 页面布局

- 左栏：真实页面缩略图和风险标记。
- 中栏：分页后的纸张预览。
- 右栏：全局样式或当前选中内容块的局部排版设置。
- 顶部：讲义版本、学生/教师配置、打印检查、保存、发布和导出。

### 9.3 全局页面设置

| 编号 | 需求 | 优先级 |
|---|---|---|
| HND-001 | A4/A3 与纵向/横向 | P0 |
| HND-002 | 上下左右页边距 | P0 |
| HND-003 | 字体、字号、行距、段前段后和标题层级 | P0 |
| HND-004 | 页眉、页脚、页码和首页差异设置 | P0 |
| HND-005 | 单栏、双栏及大题跨栏 | P1 |
| HND-006 | 学生版、教师版和自定义输出配置 | P0 |
| HND-007 | 预设版式与恢复默认 | P1 |

### 9.4 内容块局部排版

| 编号 | 需求 | 优先级 |
|---|---|---|
| HND-010 | 题目前强制分页 | P0 |
| HND-011 | 题干与首个选项尽量同页 | P0 |
| HND-012 | 题图与对应题干尽量同页 | P0 |
| HND-013 | 短题禁止跨页，长题允许自然跨页 | P0 |
| HND-014 | 单题图片宽度、对齐、题注和环绕策略 | P0 |

| HND-016 | 当前块紧凑、标准、宽松间距 | P1 |
| HND-017 | 当前块单栏、双栏或跨栏 | P1 |
| HND-018 | 显示分页原因和溢出原因 | P2 |

### 9.5 内容编辑

讲义排版允许进行轻量内容修正，如修改错字、公式、选项和图片。

规则：

1. 修改的是共享项目题目实例，不创建讲义专属题目副本。
2. 修改前明确提示“内容修改会同步到本教学项目”。
3. 页面尺寸、图片显示宽度、分页规则属于讲义产物，不写入共享内容。
4. 若需要仅在某个输出版本隐藏内容，应使用输出配置，不删除共享内容。

### 9.6 分页和性能

- 每次有效设置变化触发防抖分页。
- 字体、图片和公式加载完成后才确认页数。
- 新分页结果生成前保留上一版页面，避免预览闪空。
- 只提交最后一次分页任务结果，过期任务必须取消或丢弃。
- 100 道常规题目的重新分页目标时间不超过 5 秒；局部样式变化优先争取 2 秒内完成。
- 分页失败时保留内容预览并显示具体原因，不显示无法理解的技术错误。

### 9.7 打印检查和导出

打印检查项目：

- 空白页。
- 孤立标题。
- 题干与选项分离。
- 题图被裁切或分离。
- 公式越界。
- 表格越界。
- 页脚与正文重叠。
- 页面填充率过低或过高。
- 教师版答案缺失。

输出要求：

- PDF 使用与讲义预览相同的 HTML、CSS 和分页结果。
- Word 输出保留标题层级、题号、图片、答案、解析、页边距和页眉页脚。
- Word 预览应明确标注为“Word 兼容预览”，不作为 PDF 分页依据。
- 导出任务进入任务中心，可查看进度、失败原因和重新导出。

## 10. 课件制作需求

### 10.1 工作台目标

把共享教学内容转化为适合屏幕展示和分步讲解的课件。课件不是讲义页面截图，也不是内容文档的简单逐块复制。

### 10.2 页面布局

- 左栏：幻灯页缩略图，可拖动、分组、复制和删除。

- 发布前检查缺失图片、溢出文本、空白页和无效公式。
- 发布生成不可变版本，并记录内容版本和课件版本。
- 支持将某个发布版本设为默认授课版本。
- PPTX 导出属于附加输出；课堂播放应优先使用系统原生课件版本，避免 PowerPoint 兼容差异成为主链路依赖。

## 11. 课堂授课需求

## 12. 模板中心需求

### 12.1 模板设计原则

模板必须按作用域拆分。用户应用模板前应明确知道它会改变内容、讲义还是课件。

### 12.2 模板类型

#### A. 内容结构模板

定义教学内容的结构和规则，例如：

- 试卷：选择题、实验题、计算题、总分和题量约束。
- 讲练案：学习目标、知识梳理、例题、训练、总结。
- 专题复习：考点、方法、易错点、分层训练。

可以包含空内容槽位，但默认不包含具体题目。

#### B. 讲义样式模板

定义：

- 纸张和页边距。
- 字体、字号、行距和标题样式。
- 页眉页脚。
- 题号、选项、题图和答案解析样式。
- 默认分页策略。

不得包含知识点生成方式或具体题目。

#### C. 课件主题模板

定义：

- 画布比例、颜色、字体和背景。
- 标题页、知识页、题目页、总结页的版式。
- 默认动画或揭示风格。

#### D. 课件生成策略模板

定义：

- 内容节点如何转换成幻灯页。
- 一题一页或分步拆页规则。
- 知识、例题、训练和总结的顺序。

#### E. 项目模板

组合引用内容结构模板、讲义样式模板、课件主题和生成策略，用于一键创建完整教学项目。

项目模板可以选择包含示例内容；如果包含题目，应复制为新项目题目实例，而不是保持可变引用。

### 12.3 模板操作

| 编号 | 需求 | 优先级 |
|---|---|---|
| TPL-001 | 按模板类型浏览、搜索和筛选 | P0 |
| TPL-002 | 预览模板作用范围和示例效果 | P0 |
| TPL-003 | 从当前项目提取指定作用域为模板 | P0 |
| TPL-004 | 应用模板前显示将改变的字段 | P0 |
| TPL-005 | 选择“仅填充未设置项”或“覆盖当前设置” | P1 |
| TPL-006 | 模板版本、复制、重命名、归档和删除 | P1 |
| TPL-007 | 学校公共模板和个人模板 | P2 |

### 12.4 模板应用规则

- 讲义样式模板只能在讲义排版或新建项目时应用。
- 课件主题模板只能在课件制作或新建项目时应用。
- 内容结构模板在组卷工作台应用。
- 项目模板在创建项目时应用。
- 模板应用后生成项目内配置副本；模板后续更新不自动改变既有项目。
- 如需同步模板新版本，应提供差异预览。

## 13. 版本、同步与发布

### 13.1 版本层级

系统需要区分以下版本：

1. 题库原题版本。
2. 教学内容文档版本。
3. 讲义排版版本。
4. 课件编辑版本。
5. 讲义发布版本。
6. 课件发布版本。
7. 模板版本。

### 13.2 状态定义

#### 内容状态

- `draft`：正在编辑。
- `ready`：内容检查通过。
- `archived`：已归档。

#### 产物状态

- `not_created`：尚未生成。
- `draft`：正在编辑。
- `stale`：来源内容已更新，尚未确认同步。
- `ready`：检查通过，可以发布。
- `published`：存在已发布版本。
- `changed_after_publish`：发布后又有新修改。

### 13.3 发布规则

- 发布前必须保存当前草稿。
- 发布快照包含渲染所需的全部内容和资源引用。
- 发布记录创建人、创建时间、来源内容版本和检查结果。
- 已发布版本不可覆盖，只能新增版本或取消默认标记。
- 删除项目时已发布版本应进入回收站，避免课堂链接立即失效。

## 14. AI 能力边界

AI 可以辅助：

- 根据规则推荐或补充题目。
- 生成知识卡、方法总结和易错提醒。
- 生成组卷结构建议。
- 将教学内容拆分为课件页。
- 生成课件讲解步骤和教师备注。
- 检查内容完整性、版面风险和讲授节奏。

AI 不得：

- 未经确认直接覆盖教师修改。
- 自动写回题库原题。
- 在没有差异说明的情况下重建已人工编辑课件。
- 把 AI 生成状态和打印排版设置混入同一个模板作用域。

所有 AI 生成结果应记录生成来源，并支持接受、局部接受、重新生成和撤销。

## 15. MCP 能力需求

### 15.1 MCP 产品定位

MCP 是 Physics Vault 对外提供的受控业务操作协议，使 AI 助手、Codex、Claude、自动化脚本或其他兼容客户端能够在教师授权下读取和操作教学项目。

MCP 不应成为另一套绕过应用服务和权限校验的后门，也不等同于云端 AI：

- MCP 工具调用现有应用服务，与网页端共享校验、版本、任务和审计机制。
- 本地查询、内容编排、模板应用、导出和版本管理在没有云端模型时仍可通过 MCP 工作。
- 需要大模型生成的能力可以在离线模式下返回明确的“生成服务不可用”，但不得影响其他 MCP 工具。
- 网页端 AI 助手应通过同一套 MCP 业务工具执行操作，不直接修改浏览器状态或数据库。

目标交互示例：

```text
教师：从牛顿第二定律题库中选 8 道题，按难度递进，建立一份 40 分练习。
MCP：查询题目 → 返回组卷方案预览 → 教师确认 → 创建项目并加入题目实例

教师：把第 3 题改成开放式设问，保留原题来源。
MCP：读取项目题目 → 返回字段差异 → 教师确认 → 更新项目题目实例

教师：讲义改成 A4 双栏，图片统一 70%，检查分页后导出学生版 PDF。
MCP：预演排版变更 → 应用讲义设置 → 提交分页检查 → 提交 PDF 任务

教师：把最新内容同步到课件，但保留我手动修改过的页面。
MCP：计算课件差异 → 自动页与人工页分类 → 返回同步计划 → 教师确认 → 应用同步
```

### 15.2 MCP 架构边界

```text
MCP Client / 网页 AI 助手
          ↓
MCP Server（参数校验、权限、确认、协议包装）
          ↓
Application Services（项目、内容、讲义、课件、课堂、模板）
          ↓
Repositories / Task Center / Audit Log
```

强制要求：

1. MCP Server 不直接拼接 SQL 修改业务数据。
2. 网页端与 MCP 端调用相同的应用服务。
3. 所有写工具接收目标对象 ID 和基准版本。
4. 所有覆盖性操作支持预演或差异返回。
5. 所有长任务进入统一任务中心。
6. 所有重要写操作进入变更审计并可追踪调用来源。

### 15.3 页面上下文与作用域

网页端调用 MCP 时，应显式提供当前上下文，避免模型猜测当前对象：

```ts
interface McpOperationContext {
  projectId?: string;
  workspace: 'library' | 'compose' | 'handout' | 'slides' | 'classroom' | 'templates';
  contentRevision?: number;
  artifactId?: string;
  artifactRevision?: number;
  selectedNodeIds?: string[];
  activePageId?: string;
  outputProfile?: 'student' | 'teacher' | 'custom';
  locale: 'zh-CN';
}
```

上下文规则：

- 页面只发送完成当前任务所需的最小上下文。
- `selectedNodeIds` 为空时，工具不得默认修改整个项目。
- 用户指令中的明确对象 ID 优先于页面当前选择，但应在执行前显示目标名称。
- 上下文版本落后时返回冲突，不自动用旧版本覆盖最新内容。
- MCP 客户端不得把“当前页面”作为永久状态；每次写操作都必须携带明确目标。

### 15.4 MCP Resources

使用 MCP Resource 暴露稳定、可读、可引用的业务上下文。建议资源 URI：

```text
physics-vault://projects
physics-vault://projects/{projectId}
physics-vault://projects/{projectId}/content
physics-vault://projects/{projectId}/diagnostics
physics-vault://projects/{projectId}/handouts
physics-vault://projects/{projectId}/slides
physics-vault://artifacts/{artifactId}/versions
physics-vault://templates
physics-vault://tasks/{taskId}
physics-vault://classroom/sessions/{sessionId}
```

资源要求：

- 资源默认只读。
- 大型内容支持分页、摘要和按节点读取，避免一次传输整份百题文档。
- 题目资源可按 `summary`、`content`、`full` 三个详细级别读取。
- 资源返回稳定 ID、版本号、更新时间和来源关系。
- 课堂会话资源默认不包含学生身份信息。
- 媒体资源优先返回受控资源 URI 和元数据，不默认将大图片编码到上下文。

### 15.5 MCP Prompts

MCP Prompt 用于提供经过产品约束的任务入口，不替代 Tool：

| Prompt | 作用 |
|---|---|
| `create_practice_project` | 根据知识点、题量、分值和难度创建练习方案 |
| `review_composition` | 检查题量、分值、知识覆盖和内容完整性 |
| `optimize_handout_layout` | 根据页数目标和可读性提出讲义排版方案 |
| `generate_slide_plan` | 将教学内容规划为幻灯页和揭示步骤 |
| `sync_slides_safely` | 比较内容与课件版本，生成不覆盖人工页的同步计划 |
| `preflight_teaching_project` | 在打印、发布或授课前执行综合检查 |

Prompt 必须输出可读计划并调用领域工具完成操作，不能要求模型直接生成数据库对象。

### 15.6 工具设计公共规范

#### 15.6.1 命名

新工具使用稳定的动词加领域对象命名：

```text
list_*
get_*
search_*
create_*
preview_*
update_*
apply_*
publish_*
submit_*
restore_*
```

兼容现有 `composition_workbench` 工具名称，新增项目模型后可提供别名和弃用周期，不得直接导致既有客户端失效。

#### 15.6.2 写入参数

所有写工具统一支持以下公共字段中的适用部分：

```ts
interface McpWriteOptions {
  baseRevision: number;
  idempotencyKey: string;
  dryRun?: boolean;
  confirmed?: boolean;
  reason?: string;
}
```

- `baseRevision`：乐观并发控制。
- `idempotencyKey`：客户端重试时防止重复写入、重复导出或重复发布。
- `dryRun`：只返回影响范围和差异。
- `confirmed`：高风险操作的明确确认标记。
- `reason`：写入题库、发布、恢复版本等操作的审计说明。

#### 15.6.3 标准响应

```ts
interface McpToolResult<T> {
  ok: boolean;
  data?: T;
  preview?: {
    summary: string;
    changes: ChangePreviewItem[];
    affectedCount: number;
  };
  warnings: McpWarning[];
  revision?: number;
  auditBatchId?: string;
  taskId?: string;
  nextActions?: McpNextAction[];
  error?: {
    code: string;
    message: string;
    retryable: boolean;
    details?: Record<string, unknown>;
  };
}
```

工具结果必须同时适合机器处理和教师阅读，不以自然语言字符串代替稳定字段。

### 15.7 权限与确认等级

| 等级 | 操作类型 | 示例 | 默认确认 |
|---|---|---|---|
| R0 | 只读 | 查询项目、预览题目、读取检查报告 | 不需要 |
| R1 | 可撤销草稿修改 | 调整顺序、修改项目题目、应用局部样式 | 用户明确指令后可执行 |
| R2 | 生成或状态变更 | 批量应用方案、发布课件、恢复版本、导出文件 | 执行前展示摘要并确认 |
| R3 | 高风险或影响题库 | 删除项目、覆盖模板、写回题库原题、批量回滚 | 必须二次确认及 `confirmed=true` |

额外规则：

- 模糊指令不得推断为 R2 或 R3 操作。
- “优化一下”只允许生成建议或预演，不允许直接覆盖整个项目。
- 删除、写回题库、版本恢复和批量覆盖必须返回具体影响对象数量。
- MCP 客户端不能代替教师确认自己发起的高风险操作。
- 授课中的翻页属于即时操作，但跳转、清屏或结束会话需要明确目标和会话状态校验。

### 15.14 计划、预演与原子应用

复杂操作采用两阶段模式：

```text
用户指令
  ↓
plan_* / preview_* 工具
  ↓
返回 planId、基准版本、差异、警告和影响数量
  ↓
教师确认或修改计划
  ↓
apply_* 工具携带 planId、baseRevision、idempotencyKey
  ↓
事务写入、增加版本、记录 auditBatchId
```

适用操作：

- 批量组卷和重排。
- 模板覆盖应用。
- 课件生成和同步。
- 批量修改项目题目。
- 发布前自动修复。
- 写回题库。

计划默认有有效期；目标版本变化后计划失效，必须重新生成。

### 15.15 并发、锁和幂等

- 读取工具返回当前 `revision`。
- 写工具携带 `baseRevision`，不一致时返回 `REVISION_CONFLICT`。
- 批量计划工具可申请短期编辑锁，但不得长期阻止网页端编辑。
- 锁信息包括持有者、来源客户端、获得时间和到期时间。
- 客户端超时重试必须复用 `idempotencyKey`。
- 相同幂等键和相同参数返回原结果；相同键不同参数返回错误。
- 发布、导出、创建项目和批量写入必须幂等。

兼容现有 `lock_composition_workbench`，后续演进为统一项目编辑租约，而不是永久锁。

### 15.16 长任务和通知

以下操作进入任务中心：

- PDF、DOCX、PPTX 导出。
- 真实讲义分页和批量打印检查。
- 大规模题目检索与组卷推荐。
- AI 知识卡或课件生成。
- 批量媒体检查。

MCP 工具返回 `taskId`，并提供：

- `get_job_status`
- `list_jobs`
- `retry_job`
- `cancel_job`

任务结果应包含可下载产物、检查报告或结构化失败原因。支持 MCP 通知时，可推送进度变化；不支持通知时由客户端轮询，但建议最短间隔不低于 1 秒。

### 15.17 审计、回滚与来源标记

所有 MCP 写入记录：

- 操作工具名称。
- MCP 客户端名称和会话 ID。
- 用户身份。
- 目标项目、产物和节点。
- 变更前后版本。
- 参数摘要和用户确认状态。
- 是否由模型生成或由用户明确指定。
- `auditBatchId`、时间和执行结果。

可撤销的批量写入应复用现有变更批次机制：

- `list_change_batches`
- `get_change_batch`
- `rollback_change_batch`

回滚本身也是新的审计操作，不删除原始历史。

### 15.18 隐私与数据最小化

- 默认不通过 MCP 暴露 API 密钥、数据库路径和系统绝对路径。
- 题库、讲义和课件资源只返回完成任务所需字段。
- 外部模型调用前显示是否会发送题目正文、图片和教师备注。
- 学生姓名、班级名单和课堂记录默认不进入模型上下文。
- 媒体上传、下载和读取使用受控资产 ID，不允许客户端任意读取本地文件。
- 服务端记录外部提供方、模型和数据范围，供审计查询。

### 15.19 错误码与恢复建议

新增或统一以下业务错误：

| 错误码 | 含义 | 客户端建议 |
|---|---|---|
| `PROJECT_NOT_FOUND` | 教学项目不存在 | 刷新项目列表 |
| `ARTIFACT_NOT_FOUND` | 讲义或课件不存在 | 重新选择产物 |
| `REVISION_CONFLICT` | 基准版本已过期 | 读取最新版本并重新生成计划 |
| `PLAN_EXPIRED` | 操作计划失效 | 重新预演 |
| `CONFIRMATION_REQUIRED` | 操作风险级别要求确认 | 显示影响摘要并请求用户确认 |
| `SCOPE_VIOLATION` | 模板或工具超出允许作用域 | 修正目标范围 |
| `ARTIFACT_STALE` | 产物来源内容不是最新版本 | 先查看同步差异 |
| `PUBLISHED_VERSION_REQUIRED` | 授课缺少已发布课件 | 引导发布课件 |
| `CLASSROOM_SESSION_INACTIVE` | 课堂会话已结束或不存在 | 重新开始会话 |
| `AI_PROVIDER_UNAVAILABLE` | 生成服务不可用 | 保留本地工具并允许稍后重试 |
| `TASK_IN_PROGRESS` | 相同幂等任务仍在执行 | 返回原任务 ID |

错误响应必须提供 `retryable` 和建议下一步，不返回内部堆栈或敏感路径。

### 15.21 MCP 验收标准

#### 组卷与题目编辑

- MCP 能创建教学项目并加入题库题目，项目中保存完整题目实例。
- MCP 修改项目题干后，网页刷新仍能看到修改，题库原题不变。
- 过期内容版本执行修改时返回 `REVISION_CONFLICT`，不覆盖新内容。
- 同一 `idempotencyKey` 重试不会重复加题。

#### 讲义

- MCP 可以预演并应用页边距、字体和指定题目图片宽度。
- MCP 能提交真实分页检查并在任务完成后读取页数与风险。
- MCP 提交的 PDF 导出与网页讲义预览使用相同产物版本。

#### 课件与授课

- MCP 能生成课件计划，经确认后创建课件草稿。
- 内容更新后可以读取课件差异，并保留人工修改页完成同步。
- MCP 只能使用已发布课件版本创建正式课堂会话。
- 会话翻页后返回的页面状态与课堂屏幕一致。

#### 安全与审计

- 发布、恢复、删除、模板覆盖和题库写回均按风险等级要求确认。
- 每个 MCP 写入均可在审计记录中定位到工具、客户端、目标和版本。
- 可撤销批量操作能通过审计批次回滚，且回滚产生新记录。
- AI 服务关闭后，查询、编辑、模板、版本和导出等本地 MCP 能力仍然可用。

## 16. 非功能需求

### 16.1 数据可靠性

- 服务端数据库是项目和产物草稿的唯一可信来源。
- 本地缓存用于性能和异常恢复。
- 项目题目完整快照必须可在题库不可用时独立恢复。
- 每次覆盖性操作必须可撤销或从版本恢复。

### 16.2 性能

- 打开 100 题项目首屏目标不超过 3 秒，内容可分段加载。
- 普通编辑自动保存反馈目标不超过 1 秒。
- 讲义重新分页目标不超过 5 秒。
- 课堂翻页和分步揭示响应目标低于 100 毫秒。

### 16.3 兼容性

- 首期支持最新版 Edge 和 Chrome。
- 主要输出支持 PDF、DOCX 和 PPTX。
- PDF 是纸面版式基准；DOCX 和 PPTX 属于兼容输出。

### 16.4 可访问性与课堂可用性

- 关键按钮有明确文字和键盘焦点。
- 课堂模式支持高对比度和放大。
- 不依赖颜色作为唯一状态提示。

### 16.5 审计

记录以下操作：

- 项目题目写回题库。
- 模板覆盖应用。
- 发布和取消默认版本。
- 版本恢复。
- 删除项目或产物。

## 17. 当前实现审视与差距

### 17.1 可保留的基础

现有代码已经具备以下良好基础：

- 已拆分 `/compose`、`/handout`、`/slides`、`/classroom` 和 `/templates` 页面。
- `LessonDocumentV2` 已包含题目快照和覆盖字段的概念。
- `TeachingProject` 已开始区分共享内容、讲义产物和课件产物。
- 课件已具备来源内容版本与待同步提示。
- 讲义已具备分页预览、打印检查、版本和导出入口。
- MCP Server 已具备题目查询、组卷工作台创建与调整、讲义读取、Word 格式模板、导出任务、任务状态和变更批次回滚能力，可作为新项目 MCP 的兼容基础。

### 17.2 P0 差距

#### 差距 1：组卷题目修改未可靠持久化

当前组卷草稿的题目项主要保存：

- `question_id`
- 题型
- 难度
- 来源

重新加载草稿时，再根据 `question_id` 从题库读取题目。因此组卷页对题干、选项、答案和解析的局部修改没有形成稳定的服务端项目题目实例。

修复要求：草稿保存完整项目题目内容，加载时优先读取项目题目实例，不重新用题库内容覆盖。

#### 差距 2：组卷页职责过重

组卷页当前包含讲义纸张模拟、页眉页脚、打印排版、课件预览、PPTX 导出和授课入口。应将组卷页收敛为内容结构与编辑工作台。

#### 差距 3：多套存储形成多个真相来源

当前存在当前教学包、本地教学项目、服务端组卷草稿、已保存讲义等多种保存形式。需要以服务端教学项目为主对象，其他存储作为迁移兼容或缓存。

#### 差距 4：讲义和课件分别维护文件树

讲义页和课件页都围绕教学包保存自己的文件列表，用户难以理解它们是否属于同一作品。应改为教学项目作品库，再在项目内部管理多个产物。

#### 差距 5：课件语义不一致

界面文字宣称课件“不再单独维护一套页面数据”，但实际上课件已经允许移动、复制和保存独立幻灯页。正确产品语义应为：共享内容来源，独立维护课件表现与讲授结构。

#### 差距 6：课堂读取草稿而不是发布快照

课堂授课目前根据当前教学包和课件状态生成页面。正式课堂应绑定已发布课件版本，避免编辑变化影响课堂。

#### 差距 7：模板作用域混合

当前模板同时包含排版、答案解析显示、知识点生成和课件相关设置，并从模板页“应用到组卷工作台”。需要拆成内容结构、讲义样式、课件主题、课件生成策略和项目模板。

#### 差距 8：MCP 尚未覆盖完整教学项目产物链路

现有 MCP 主要覆盖题库、校对、组卷草稿、已保存讲义和导出任务，尚缺统一教学项目、项目题目完整实例、讲义局部排版、课件差异同步与发布、课堂会话、分作用域模板等工具。

迁移要求：保留现有工具作为兼容入口，将其内部逐步切换到统一应用服务和教学项目模型；不得同时维护两套互不一致的 MCP 写入逻辑。

## 18. 迭代路线

### 阶段一：数据正确与职责拆分（P0）

目标：先保证教师修改不会丢，页面职责清晰。

1. 建立服务端 `TeachingProject` 和 `TeachingContentDocument`。
2. 题库题目加入项目时保存完整项目题目实例。
3. 迁移现有组卷草稿，兼容旧 `question_id` 引用。
4. 从组卷页移除纸张排版、PDF/Word、PPTX 和授课控制。
5. 讲义页只维护讲义表现，内容修正写回共享内容文档。
6. 课件页保存独立课件产物和来源内容版本。
7. 课堂授课绑定课件发布快照。
8. 将本地存储降级为缓存和恢复手段。
9. 建立教学项目、项目题目、讲义、课件和发布版本的 P0 MCP 读写工具。
10. 为 MCP 写操作加入基准版本、幂等键、风险确认和审计批次。

阶段验收：

- 修改项目题目后刷新和重新登录仍保持修改。
- 题库原题不发生变化。
- 组卷、讲义、课件均从同一项目进入。
- 上课时编辑课件草稿不会影响正在授课的版本。
- MCP 修改项目题目不会修改题库原题，也不会因重试产生重复内容。

### 阶段二：可用的产物工作流（P1）

1. 教学项目作品库和统一状态卡片。
2. 讲义真实分页、缩略图、局部排版和打印检查。
3. 课件页编辑、拆页、揭示顺序、教师备注和预演。
4. 内容到课件的逐页差异同步。
5. 版本历史、发布和默认版本管理。
6. 模板按作用域拆分并支持差异应用。
7. 补齐 MCP Resources、Prompts、课件差异同步、课堂会话和任务通知。

### 阶段三：智能化与课堂沉淀（P2）

1. AI 组卷结构建议和课件拆页建议。
2. 课堂批注保存与复盘。
3. 项目、模板和课件的团队共享。
4. 授课数据、课堂反馈与错题回流。
5. 平板遥控、教师屏与投影屏分离。

## 19. 总体验收标准

### 19.1 内容一致性

- 同一个项目题目在组卷页和讲义页显示相同内容。
- 在讲义页修改题干后返回组卷页可立即看到修改。
- 课件同步时能识别该题发生变化，不自动覆盖人工课件页。
- 题库原题保持不变。

### 19.2 讲义

- 预览显示独立纸张和真实页数。
- PDF 页数、分页和页眉页脚与预览一致。
- 改变页边距、字体、图片宽度后重新分页生效。
- 不出现打印容器滚动条。
- 常见长题、图片题和公式题没有不可接受的截断。

### 19.3 课件与授课

- 可以从内容生成课件、人工调整并保存。
- 内容更新后课件显示待同步状态和差异数量。
- 发布后可以选择指定版本开始授课。
- 授课播放与课件预演一致。
- 正在进行的授课不受新编辑或新发布版本影响。

### 19.4 模板

- 用户能够明确区分内容结构、讲义样式和课件主题。
- 应用模板前可以看到作用范围。
- 讲义模板不会修改题目文本和课件主题。
- 课件主题不会修改讲义页边距和答案显示规则。

### 19.5 MCP

- MCP 能读取当前项目、选中内容和准确版本，不依赖模型猜测页面状态。
- MCP 对复杂修改先返回计划和差异，经确认后原子应用。
- MCP 修改、导出、发布和回滚结果可在网页端立即看到。
- MCP 写入具备幂等、并发冲突保护、权限确认和审计记录。
- MCP 的讲义、课件和课堂工具遵守各工作台的数据边界。

## 20. 产品决策摘要

1. “教学项目”成为五个工作流的共同容器。
2. 组卷工作台改为“组卷与内容”，只负责内容选择、结构和编辑。
3. 题库题目进入项目后生成完整、独立、可编辑的项目题目实例。
4. 讲义与课件共享内容来源，但分别保存排版和讲授结构。
5. 讲义草稿实时读取共享内容；课件因允许深度人工编辑，采用显式差异同步。
6. 课堂授课只读取已发布课件版本。
7. 模板按作用域拆分，不再用一个模板同时控制内容生成、打印样式和课件。
8. 服务端教学项目是唯一可信数据源，本地存储只做缓存和异常恢复。
9. PDF 与讲义预览追求完全一致；Word 与 PPTX 只承诺内容和基础样式兼容。
10. 先修复数据正确性和页面职责，再继续增加高级排版和 AI 功能。
11. MCP 是贯穿教学项目全链路的受控业务接口，不是绕过应用服务的数据库写入通道。
12. MCP 与网页端共享版本、任务、权限和审计；复杂写操作采用“计划/预演—确认—原子应用”。
13. MCP 不等于云端 AI，本地查询、编辑、模板、版本和导出在 AI 服务关闭时仍应可用。
