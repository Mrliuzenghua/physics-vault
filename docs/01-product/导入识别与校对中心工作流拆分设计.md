# 导入识别与校对中心工作流拆分设计

## 目标

导入识别不做成单个长任务，而是拆成可观察、可暂停、可重试、可部分完成的小环节。任一环节失败时，不影响已经完成的结果，用户可以继续处理其他文件或其他题目。

## 核心原则

1. 每个文件独立成任务。
2. 每个任务拆成多个阶段。
3. 每个阶段有明确输入、输出、状态和错误信息。
4. 模型调用按题目或页面分片，并发执行。
5. 失败只影响当前分片，不阻塞整批任务。
6. 校对中心只处理“已经产生的题目草稿”，不等待整份材料完全成功。

## 拆分后的主流程

```text
导入任务
  1. 上传材料
  2. 预处理
  3. 分页 / 提图 / 转 Markdown
  4. 切题
  5. OCR / AI 结构化
  6. AI 初校
  7. 风险检测
  8. 进入校对中心
  9. 人工确认
  10. 入库
```

## 阶段设计

### 1. 上传材料

输入：Word、PDF、图片、Markdown、纯文本。  
输出：batch_id、源文件路径、文件类型、文件大小。  
失败处理：只提示当前文件上传失败，不影响其他文件。

### 2. 预处理

Word / Markdown / 文本：
- 转 Markdown
- 提取图片
- 生成媒体清单

PDF / 图片：
- PDF 渲染为页面图片
- 图片标准化
- 生成页面清单

输出：页面列表或 Markdown 文本、图片资源清单。  
失败处理：允许重新跑预处理；如果部分页面成功，保留成功页面。

### 3. 切题

输入：Markdown 或 OCR 文本。  
输出：题目草稿列表。  
状态：
- 成功切题
- 疑似切题失败
- 空题
- 需要人工拆分

失败处理：进入校对中心的“切题异常”队列，而不是让整个任务失败。

### 4. OCR / AI 结构化

拆分粒度：
- PDF 按页并发
- 图片按文件并发
- Word 切题后按题目分批结构化

建议默认并发：
- OCR / VL：1-2
- LLM 清洗 / 初校：2-4

输出：标准题目 JSON 草稿。  
失败处理：当前页或当前题标记为“识别失败”，其他分片继续。

### 5. AI 初校

输入：题目草稿。  
按题目或每 3-5 题一组并发调用。  
输出：
- 修正后的题干
- 选项
- 答案
- 解析
- 题型
- 难度
- 标签
- 知识点

失败处理：保留原始草稿，标记“AI 初校失败”，允许单题重试。

### 6. 风险检测

规则检测，不依赖模型：
- 题干为空
- 选择题无选项
- 有选项但无答案
- 图片占位符存在但图片缺失
- 图片存在但题干未引用
- 解析疑似混入下一题
- 题号不连续
- 题型与选项不匹配

输出：风险标签。  
校对中心优先展示高风险题。

## 校对中心视角

校对中心不等待整批导入全部结束，只要有题目草稿产生，就可以开始校对。

左侧队列：
- 全部
- 待校对
- 高风险
- AI 初校失败
- 已确认
- 已丢弃

中间编辑：
- 题干
- 选项
- 答案
- 解析
- 图片
- LaTeX 预览

右侧操作：
- 确认当前题
- 丢弃当前题
- 合并下一题
- 拆分题目
- 重跑当前题 AI 校对
- 补全元数据

底部批量操作：
- 确认所有无风险题
- 批量 AI 初校失败重试
- 批量补全标签和知识点
- 保存已确认题入库

## 并发执行建议

统一封装一个受限并发执行器：

```text
run_with_concurrency(items, concurrency, worker)
```

每个 item 独立返回：
- success
- skipped
- failed
- error
- output

适用场景：
- 多页 OCR
- 多题 AI 初校
- 多题生成解析
- 多题补全元数据

## 用户体验变化

旧体验：
用户点击开始后只能等，某一步失败就不知道前面结果是否还在。

新体验：
用户可以看到每个环节的状态；一页失败不影响其他页；一题失败不影响其他题；已经识别出的题可以马上进入校对中心。

## 推荐迭代顺序

1. 先把前端导入页拆成“上传、策略、任务列表、最近结果”四块。
2. 后端增加分片任务状态，不再只返回最终结果。
3. 校对中心增加风险队列。
4. AI 初校改成并发分批执行。
5. OCR 改成按页并发执行。
6. 增加失败分片的单独重试。
## 已落地拆分记录

### 2026-07-28 第一轮

- 前端“导入识别”拆成独立文件任务：每个文件单独创建批次、单独识别、单独失败、单独重试。
- 前端导入任务增加有限并发：同一批材料最多同时推进 2 个文件，避免一个慢文件拖住全批。
- 前端“校对中心”拆成队列式处理：高风险、待确认、已修改、已确认、已丢弃、全部。
- 校对中心增加基础风险识别：空题干、缺答案、选择题缺选项、未标知识点、图片引用异常。
- 后端新增通用有限并发工具 `gather_limited`，供按题、按页、按批次工作流复用。
- 后端批量生成解析改为按题有限并发，默认同时处理 3 道题；单题失败只返回单题失败，不中断整批。
- 后端导入 AI 初校拆出独立执行器：按 5 题一批、最多 3 批并发；单批模型失败时保留本地解析结果，不阻塞其他批次。
- 后端 PDF 识别拆成页级任务：真实 PDF 会先渲染为页面图片，再按页并发 OCR；失败页只进入 warnings，成功页继续合并进入校对中心。
- 公式清洗增加防错层：同一行内误包成 `$$...$$` 的短公式会自动降回 `$...$`，保留独占一行的真正行间公式。
- 校对中心增强为可操作版本：新增缺答案、缺选项、图片异常、AI 失败页等细分队列；支持原始页/配图预览、确认并下一题、跳到下个风险题、确认当前队列，以及 AI 修复建议预览后采纳。

## 后端继续拆分路线

### 1. 导入任务状态持久化

目标：把“上传、预处理、识别、质检、校对”每个阶段写入批次状态，前端可以刷新后继续查看。

建议状态：

- `uploaded`
- `preprocessing`
- `page_splitting`
- `recognizing`
- `risk_checking`
- `ready_for_review`
- `partial_failed`
- `failed`

### 2. PDF / 图片按页拆分

目标：PDF 不再作为一个大模型请求处理，而是先渲染为页面图片，再按页进入 OCR。

建议流程：

- PDF 渲染为 `pages/page-0001.png` 等页面图片。
- 每页生成一个 page job。
- page job 独立调用视觉模型。
- 失败页只标记该页失败，不影响其他页。
- 所有成功页结果按页码合并，再进入题目切分与质检。

### 3. 题块级模型调用

目标：长文档不再整篇丢给模型，而是按题块、小题块或页面窗口调用。

建议策略：

- 文档解析优先本地切题。
- 对高风险题块才调用 AI 初校。
- AI 初校按 3-5 题一批，有限并发。
- 每批失败时保留本地切题结果，并进入“AI 失败/需人工校对”队列。

### 4. 模型调用调度器

目标：统一管理并发、超时、重试和熔断。

基础规则：

- 视觉模型并发建议 1-2。
- 文本模型并发建议 2-3。
- 单次调用设置硬超时。
- 连续失败达到阈值后暂停新请求，剩余任务转人工校对。
- 所有调用都返回结构化状态：`success`、`skipped`、`failed`、`timeout`。
