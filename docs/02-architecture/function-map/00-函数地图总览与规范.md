# Physics Vault：全量函数地图

> 目标：让仓库中每一个生产代码函数都能被定位、理解并安全重构。

## 1. 地图结构

函数地图分为两层：

1. **全量索引层**：逐文件列出每一个函数、方法、异步函数、React 组件与 Hook 的位置、签名和类别；以源代码扫描结果核对，防止遗漏。
2. **语义说明层**：为每个函数记录职责、输入、输出、副作用、内部调用关系、归属边界和重构提示。

## 3. 每个函数的统一记录格式

| 字段 | 说明 |
| --- | --- |
| 标识 | `文件路径:行号::函数名`，是地图中的唯一定位键 |
| 签名 | 源码中的函数或方法签名 |
| 职责 | 用一句话说明它解决的业务或技术问题 |
| 输入 → 输出 | 关键入参与返回结果；无法静态确定时明确标记 |
| 副作用 | `无`、状态更新、HTTP、文件、数据库、浏览器存储、任务/MCP 等 |
| 上游 / 下游 | 主要调用方和主要依赖；跨领域调用要注明契约 |
| 归属 | 代码地图 1、2、3 或共享基础设施 |
| 优化提示 | 保持、拆分、下沉、迁移或待确认；不得在地图中直接改变行为 |

## 5. 完成标准

- 每个分册必须列出扫描到的源文件数、函数数，以及未能静态解析的文件清单（应为零或明确原因）。
- 每个生产函数至少有一条统一记录；类方法、私有方法、异步函数、React 组件和 Hook 均不能省略。
- 函数的职责和副作用必须来自当前代码，不根据名称臆测。
- 代码变动后，变更所属工作流需要同步更新对应分册；地图是重构的前置条件而非一次性文档。
