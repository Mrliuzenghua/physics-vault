# 数据库边界优化说明

## 目标

项目按数据生命周期拆成两个明确边界，避免智能体、校对流程和正式题库互相污染：

| 数据库 | 默认路径 | 角色 | 写入规则 |
| --- | --- | --- | --- |
| 标准库 / Canonical DB | `data/app-db/physics_vault.sqlite3` | 权威题库、正式知识点、组卷、课堂展示、审计记录 | 默认只读；只有发布入库、受控批量规范化、审计回滚、管理员维护可以写入 |
| 审核库 / Review DB | `data/mcp/review_workspace.sqlite3` | 校对中心草稿、送审题、AI 生成草稿、人工复核队列、草稿修改记录 | 可读写、可批量修改；不代表正式题库 |

旧版本曾设计过 `MCP Workspace DB`，当前已经废弃。MCP 不再创建或复制第三个数据库，避免出现“正式库、审核库、MCP 工作库”三套口径。

## 校对中心规则

校对中心任务必须使用审核库，而不是标准库。

典型场景：

- “送审的 15 道题”
- “校对中心草稿”
- “待校对任务”
- “清洗送审题 LaTeX”
- “批量修改审核中的标签/年份/知识点”

这些请求必须先走：

- `list_review_tasks`
- `get_review_task`
- `get_review_task_full`
- `clean_review_task_latex`
- `update_review_task_draft`

禁止先用正式库工具 `search_questions` / `get_questions_by_ids` 定位这批题，因为它们可能尚未正式入库。

## 标准库写入通道

标准库不暴露自由写权限，只保留三类受控入口：

1. `Review Publish`：人工审核确认后发布入库。
2. `Controlled Batch Normalization`：年份、标签、知识点等批量规范化，必须支持 dry-run、人工确认和审计记录。
3. `Admin Maintenance`：备份、恢复、迁移、标准数据集重建。

## MCP 工具边界

| 工具类型 | 代表工具 | 数据库边界 |
| --- | --- | --- |
| 正式库只读 | `search_questions`、`get_questions_by_ids`、`list_knowledge_tree`、`list_question_tags` | 只读 `Canonical DB` |
| 审核库读写 | `list_review_tasks`、`get_review_task`、`update_review_task_draft`、`clean_review_task_latex`、`submit_ai_generated_review` | 读写 `Review DB` |
| 受控标准库写入 | `batch_replace_question_tags`、`batch_replace_question_knowledge_points`、`return_question_to_review` | 必须先 dry-run，确认后写入 `Canonical DB` 并记录审计 |
| 审计与回滚 | `list_change_batches`、`get_change_batch`、`rollback_change_batch` | 读取审计记录；回滚也必须先 dry-run，确认后才写标准库 |
| 边界自检 | `database_boundary_report`、`database_health_report` | 只读；用于防止智能体走错库 |

## 审计表

受控写入会在标准库中维护两张审计表：

| 表 | 作用 |
| --- | --- |
| `change_batches` | 一次批量变更的批次、类型、原因、影响数量和应用时间 |
| `change_items` | 每个实体字段的修改前值、修改后值、风险等级和所属批次 |

## 维护原则

- 标准库中的历史 `import_pipeline_tasks`、`review_workspace_ignored_sessions`、旧 `review_queue` 都不再作为有效校对中心来源。
- 如果发现标准库仍有审核/送审类历史表，应先备份，再迁移或删除，保持两库边界清晰。
- 不确定该查哪个库时，MCP 应优先调用 `database_boundary_report`。
