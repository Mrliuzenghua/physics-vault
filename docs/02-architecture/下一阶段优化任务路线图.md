# Physics Vault 下一阶段优化任务路线图

> 目标：先收口 MCP、写操作安全和任务可观测性，再建设检索质量与教学版本能力。

## 1. 总体顺序

```text
MCP 注册层
  → MCP 领域拆分
  → 统一写操作协议
  → API 契约收口
  → 全链路任务追踪
  → 检索质量工作台
  → 教学项目版本化
  → 前端性能优化
```

## 2. 第一阶段：MCP 注册层与领域拆分

### MCP-001：建立声明式工具注册表

- **目标**：让工具名称、领域、风险等级、只读/写入属性、输入模型和处理函数集中声明。
- **建议新增**：`packages/mcp_contracts/src/tool_registry.py` 或后端等价模块。
- **只读参考**：`scripts/physics_vault_mcp_server.py`。
- **输出**：`ToolSpec`、领域枚举、风险枚举、工具发现接口。
- **保持兼容**：现有工具名称和参数不变。
- **验收**：注册表工具数与 MCP 实际暴露数一致；重复名称启动失败；可按领域/风险筛选。

### MCP-002：抽离 MCP 公共基础设施

- **目标**：从 MCP 巨型入口抽出数据库连接、服务工厂、参数清洗、错误载荷和审计上下文。
- **建议新增**：`packages/mcp_contracts/src/runtime/`。
- **禁止事项**：不迁移具体业务工具，不改变数据库边界。
- **验收**：入口脚本只负责装配；原有 MCP 回归测试通过；无循环依赖。

### MCP-101～105：按领域迁移工具

| 任务 | 领域 | 主要范围 | 验收重点 |
| --- | --- | --- | --- |
| MCP-101 | 检索与知识点 | 搜题、按 ID 获取、语义/方法检索、知识树 | 排序、分页和结果字段保持兼容 |
| MCP-102（已完成） | 导入与审核 | 导入、审核任务、风险检查、LaTeX/选项/重复修复 | 正式库与审核库边界不变 |
| MCP-103（已完成） | 组卷与教学 | 组卷工作台、教学项目、课堂会话、学案 | 不直接修改正式题内容 |
| MCP-104（已完成） | 导出与任务 | Typst、Word、PPTX、任务提交/查询/重试/取消 | 长任务状态和错误结构一致 |
| MCP-105（已完成） | 管理与治理 | 标签、知识点维护、重复题合并、数据库健康 | 所有写入可审计、可预览 |

每次只迁移一个领域。`scripts/physics_vault_mcp_server.py` 在迁移期间保留兼容门面，禁止一次性重写。

MCP-102 已将 14 个导入与审核工具迁入独立领域门面；公开名称、参数签名和返回结构保持兼容，正式库与审核库边界未改变。

MCP-103 已将 43 个组卷与教学工具迁入独立领域门面；authoring profile 的实际暴露集合、工具签名与旧处理器均已逐项校验。

MCP-104 已将 operations profile 的 8 个工具迁入独立领域门面；公开签名、任务服务、`trace_id` 与审计调用路径保持兼容。

MCP-105 已将 catalog maintenance profile 的 18 个管理与治理工具迁入独立领域门面；高风险工具保留既有的 `dry_run`、确认、原因与审计语义。

## 3. 第二阶段：统一写操作安全协议

### SAFE-201：定义操作计划模型

- **目标**：所有高风险 MCP/API 写操作先返回统一计划。
- **字段**：`operation_id`、`action`、`targets`、`expected_version`、`summary`、`warnings`、`expires_at`、`reversible`。
- **验收**：批量标签、知识点、审核修复、重复题合并和素材清理均能生成计划。

### SAFE-202：统一确认、幂等和并发控制（进行中：素材、审核草稿与批量元数据已接入）

- **流程**：预览 → 携带 `operation_id` 确认 → 校验版本 → 执行一次。
- **规则**：过期计划、输入版本变化和重复提交必须返回可识别错误。
- **验收**：重复确认不会重复写入；并发冲突不覆盖新数据；失败不会留下半完成状态。
- **已落地**：操作计划可持久化；支持过期、版本校验、原子执行权、完成结果重放和失败收口。同一 `operation_id` 的并发确认只允许一个执行者。三个素材清理预览均会持久化计划，`POST /api/assets/confirm-operation` 仅接受 `operation_id` 并在执行前复核当前版本。审核草稿删除与版本恢复也已使用预览—确认接口，确认请求不再携带 task、版本或恢复范围。批量元数据新增 `preview` 与 `confirm-operation`：预览会冻结每题最终更新/跳过结果和版本快照，确认只接受 `operation_id`；任何目标版本变化均返回 409 且零写入，确认不会重新调用 AI 或采用客户端更新参数。
- **并发强化**：审核草稿仓储已提供 `delete_if_version`；确认删除以 `task_id + version` 原子比较并删除，版本失配会保留最新草稿并返回 409。
- **剩余接入**：按领域将审核修复、标签、知识点和重复题合并等真实写操作接入执行内核。

### SAFE-203：统一审计与回滚入口

- **目标**：所有可逆操作记录操作者、来源、前后值和关联任务。
- **验收**：可从 MCP、API 和前端查看同一变更批次；回滚后再执行校验测试。

## 4. 第三阶段：API 契约收口

### API-301：迁移剩余根路径和裸字典响应

- 从 [API 架构目录](API-architecture-catalog.md) 逐领域领取任务。
- 新路径统一为 `/api/<domain>`；旧路径只保留兼容转发。
- JSON 路由使用具名请求/响应模型和统一错误载荷。
- **验收**：OpenAPI 无重复 operation ID；兼容路径与新路径响应等价。

### API-302：继续拆分前端领域客户端（已完成）

- 优先领域：图片、收藏、集合、错题、批注、元数据。
- `api.ts` 只保留具名兼容导出；页面不得拼接 URL 或直接 `fetch`。
- **验收**：每个领域客户端有请求级测试；旧导入调用方逐步归零。
- **已落地**：素材、收藏、集合已拆为独立 client；8 个调用方完成迁移，`api.ts` 保留同名兼容导出，三个客户端均有成功、URL 编码与错误透传测试。批注与元数据/知识点管理也已拆为独立 client，批注面板、知识树和题库浏览页完成迁移。题目客户端补齐相似题接口后，浏览、组卷、仪表盘、草稿会话和题篮也完成直连迁移；审核草稿和审核工作流客户端也已独立，冲突响应保留具名错误和当前服务端草稿，审核工作台、仪表盘和 AI 对话均已完成迁移。导入客户端覆盖上传、批处理轮询、状态恢复、重试、确认与文档处理，导入与审核工作台均已完成迁移。AI/MCP 客户端覆盖运行状态、配置、测试、题目智能体与流式事件，设置页、聊天、编辑器、状态栏和课堂反思均已迁移。组卷草稿客户端覆盖草稿读取、恢复与保存，组卷页和草稿会话均已迁移。图片缓存客户端覆盖检索与多图上传，编辑器选择器已完成迁移。系统与目录查询客户端覆盖数据库状态、健康、索引、试卷与图片查询，状态栏已迁移。`api.ts` 现仅保留兼容导出，新增调用应直接依赖领域客户端。十批测试均已纳入常规前端测试命令。

### API-303：建立自动契约门禁（已完成）

- 检查 Router 重复路径、缺失响应模型、裸 `dict`、前端直接 `fetch` 和 MCP 工具重名。
- **验收**：门禁进入常规测试命令，违规提交直接失败。
- **已落地**：可使用 `./.venv/Scripts/python.exe scripts/check_contracts.py` 作为稳定检查入口；输出按违规码、位置、说明和修复建议排序，违规时以非零状态退出，适合本地提交前与 CI 使用。

## 5. 第四阶段：全链路任务追踪

### OBS-401：统一关联标识（已完成）

- **目标**：浏览器请求、HTTP API、MCP 调用、后台任务和审计记录共享 `trace_id` / `task_id`。
- **验收**：任一失败任务能反查入口请求、阶段事件和最终错误。
- **落地**：浏览器默认发送 `X-Trace-ID`；API 透传或生成该标识并在响应头返回。持久化任务、后台 worker 和任务操作审计均保存同一 `trace_id`，任务详情与 MCP 任务摘要均返回 `trace_id`。

### OBS-402：记录任务阶段事件（已完成）

- **阶段模型**：排队、读取、转换、清洗、识别、解析、写入、导出、完成。
- **字段**：开始/结束时间、耗时、输入版本、重试次数、warning、错误码和建议动作。
- **验收**：导入与 Office 导出至少各接入一条完整链路。
- **落地**：任务事件以持久化时间线记录队列、阶段开始、重试、完成/失败与 warning；包含阶段、开始/结束时间、耗时、输入版本、重试次数、错误码和建议动作。`GET /api/tasks/{task_id}/events` 可读取导入和 Word/PPTX 导出链路。

### OBS-403：升级任务中心界面（已完成）

- 展示阶段时间线、重试原因、关联产物、审计批次和安全重试按钮。
- **验收**：用户无需查日志即可判断失败阶段和下一步。
- **已落地**：任务中心可按任务查看阶段时间线、耗时、重试、warning、错误码、错误摘要、建议动作和可复制的 `trace_id`；详情加载失败不影响任务列表。`GET /api/tasks/{task_id}/context` 还提供受限产物下载地址、操作审计和服务端计算的重试许可/原因，前端仅在服务端允许时启用安全重试。

## 6. 第五阶段：检索质量工作台

### RET-501：建立黄金评测集

- 将现有检索评估脚本的数据结构沉淀为可版本化数据集。
- 记录查询、期望题目/知识点、模式、Top-K 和阈值。
- **验收**：关键词、语义和方法检索均输出 Recall@K、MRR、延迟和失败案例。

### RET-502：教师反馈闭环

- 支持标注相关、不相关、漏召回、知识点错误和排序不合理。
- 反馈进入独立记录，不直接改正式题内容。
- **验收**：反馈可关联查询、结果、模型版本和索引版本。

### RET-503：质量工作台界面

- 展示覆盖率、零结果查询、慢查询、低质量知识点和版本对比。
- 支持从失败案例进入题目或元数据修复流程。
- **验收**：可完成“发现问题 → 修复 → 重建索引 → 重新评测”的闭环。

## 7. 第六阶段：教学版本与前端性能

### VER-601：教学项目持久化版本

- 为教学项目、学案和组卷草稿保存不可变版本、作者、发布时间和来源版本。
- **验收**：可查看差异、恢复历史版本，恢复动作写入审计。

### VER-602：发布快照与导出追踪

- 每次 Word/PDF/PPTX 导出关联项目版本、模板版本和任务记录。
- **验收**：可以从导出物追溯生成它的内容与格式配置。

### PERF-601：大型依赖按页面加载（进行中）

- 优先拆分 PDF、富文本编辑器、Office 预览和导出依赖。
- **验收**：首页/浏览页首包下降；组卷、审核与导出功能无回归。
- **已落地**：路由页面已按需加载；题库浏览页的题目编辑器进一步延迟到用户打开编辑动作后才下载，并提供加载占位。编辑器内的图片缓存选择器也仅在用户实际插入图片时加载。导入与讲义工作台的文档预览组件也仅在用户打开预览时加载。PDF、Word 预览和 Paged.js 已在对应预览/分页动作中动态加载；后续继续评估富文本编辑器与分页引擎的包体拆分。

| --- | --- | --- | --- |
| AI-A：MCP 核心 | MCP-001、MCP-002 | MCP 注册、运行时公共层、入口门面 | 无 |

## 9. 统一完成定义

- 外部工具名、URL 和关键响应字段保持兼容，或提供明确迁移层。
- 新增写操作支持预览、幂等、冲突检测和审计。
- 新模块有直接单元测试；跨层流程有契约或集成测试。
- 更新 API 目录、函数地图和对应工作流交接记录。
- 后端相关测试、前端测试、lint、build 与 `git diff --check` 通过。
- 每个提交只覆盖一个任务卡，不混入缓存、运行数据或无关格式化。
