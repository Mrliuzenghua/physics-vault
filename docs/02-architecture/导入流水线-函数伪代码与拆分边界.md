# 导入流水线：函数伪代码与拆分边界

> 对应实现：`apps/api/src/physics_vault_api/services/document_pipeline.py`
> 状态：函数级基线；已完成第一步存储职责抽取（不改变业务行为）。

## 1. 这个模块现在做什么

`document_pipeline.py` 是“文件进入审核中心”这一整条链路的实现：上传、文件转换、媒体提取、文本清洗、题目切分、AI 补强、任务调度、审核任务同步和草稿确认。它目前有约 2,800 行，承担了多个本应独立的职责。

```text
上传文件
  → 创建批次与元数据
  → 文本类：Pandoc/MarkItDown → 清洗 → 本地切题 → 可选 AI 初校
  → PDF/图片：按页 OCR/VL → 结构化题目
  → 写入批次产物和任务状态
  → 审核中心读取草稿
  → 人工确认后写入审核队列
```

### 不可破坏的约束

- 识别结果是**审核草稿**，不能绕过审核流程直接改正式题库。
- 同一批次以 `content_version` 防止迟到 Worker 覆盖用户已确认/编辑的内容。
- 各阶段允许复用已完成任务；相同输入不能重复产生不一致结果。
- 模型不可用时应保留本地解析结果，并将问题写进 `warnings`，而不是丢失草稿。

## 2. 推荐的目标边界（先作为设计，不立即迁移）

| 目标组件 | 应接管的当前函数 | 只负责什么 |
| --- | --- | --- |
| `ImportBatchStorage` | 批次元数据、原子写入、版本、文件哈希、锁 | 批次目录的一致读写；已落地于 `services/import_batch_storage.py` |
| `DocumentConverter` | `PandocAdapter` | 文档转 Markdown、提取媒体；已落地于 `services/document_converter.py`，原路径兼容再导出 |
| `ImportTextRules` | 来源、难度、题目元数据与 AI 题目草稿规范化 | 无 I/O 的导入规则；首批已落地于 `services/import_text_rules.py` |
| `ImportTextCleaner` | `DocumentCleaningService` | 纯文本/Markdown 规范化；已落地于 `services/import_text_cleaner.py`，原类保留兼容门面 |
| `ImportQuestionParser` | `StructuredQuestionParsingService`、生成文本提取函数 | 文本转题目草稿，不写文件；已落地于 `services/import_question_parser.py`，原路径兼容再导出 |
| `ImportRecognitionWorkflow` | `recognize_batch` 的文件类型路由与视觉结果整形 | 按文件类型选择文本/视觉路径；通过回调复用既有阶段实现；已落地于 `services/import_recognition_workflow.py` |
| `ImportTaskCoordinator` | 后台任务、检查点、幂等恢复 | 幂等键、结果有效性、检查点、缓存复用、派发判定以及领取/完成/重试/失败状态同步已落地于 `services/import_task_coordinator.py`；实际业务阶段执行仍由流水线回调 |
| `ReviewTaskService` | 审核任务读删、沙盒知识点同步 | 审核中心视图与审核任务管理 |

迁移后 `ImportPipelineService` 只保留上述组件的编排入口，Router 不需要知道任一文件格式或任务表细节。
